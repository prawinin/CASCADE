Project KineticSketch (v2.0)

What is KineticSketch?

KineticSketch acts as a virtual chemistry lab running in a web browser in which we can type a drug name or write its SMILES notation to instantly get its 2D drawing (or we can draw manually too). It builds a 3D model of that drug, predicts how the molecule wiggles over time, and screens it against known compounds to find similar drugs and targets.

v2.0 Architecture Update: The system has been upgraded from a simple dashboard to a modular, high-performance 6-Tab Workspace (Sketch, 3D View, Conformers, ADMET, Drug Discovery, Compute). It performs complex tasks locally without freezing the UI by offloading heavy calculations to a robust background HPC Task Worker (Redis + Celery).

This project was developed by Prawin under the guidance of Dr. Rajiv K. Kar, Assistant Professor, Jyoti and Bhupat Mehta School of Health Sciences & Technology (and Associate Faculty, Centre for Nanotechnology), IIT Guwahati.

How does it work?

Step 1: Drawing, Name Search, and Chemical Coding (Input Pipeline)

When we draw a molecule or when we type a drug name, the pipeline translates it into a standard format that computers understand (SMILES).

  1. Translating a 2D Drawing into Text (SMILES): When we draw on the canvas, the browser extracts the atomic coordinates and bonds, sending them to the backend where RDKit generates the SMILES notation.
  2. Unified Smart Input Bar: The UI features an intelligent input box that automatically detects if you are typing a SMILES code (e.g. CC(=O)O) or a common drug name (e.g. Aspirin).
  3. Local Offline Search: Queries a local SQLite database containing ~2.9 million drugs.
  4. PubChem Online Fallback: Hits the NIH PubChem API for rare compounds.

Step 2: Building the 3D Shape and Coordinate Optimization

A flat drawing doesn't tell us what a molecule actually looks like in 3D space. To figure out the physical shape, angles, and distances: 1. Adding Hydrogens: Explicitly adds Hydrogen atoms essential for 3D modeling. 2. Generating 3D Coordinates (ETKDGv3): Calculates starting 3D positions based on real crystallographic rules. 3. Relaxing the Molecule (MMFF94 force field): Runs an energy minimization algorithm to let the molecule settle into its most comfortable, relaxed resting shape. 4. HPC Background Worker: [v2 Update] This generation is now completely asynchronous via Celery workers, allowing users to browse other tabs while coordinates are calculated.

Step 3: AI-Powered Molecular Motion Prediction

The molecule's 3D coordinate shape is converted into a Position Tensor and Node Features. 1. Predicting the Floppiness (RMSF): A local Multi-Task Graph Neural Network (GNN) with exactly 1.25 Million Parameters (24.99 MB MACs) predicts the Root-Mean-Square Fluctuation (RMSF) at two timescales (10 nanoseconds and 1 microsecond). To verify the new multi-task model architecture: python -c "from app.services.models import MDRepoPredictor; import torchinfo; torchinfo.summary(MDRepoPredictor(), input_data=[import('torch').randn(15,3), import('torch').randn(15,13), import('torch').ones(15, dtype=import('torch').bool)])"

  1. Orientation Independence: The GNN ignores absolute coordinates, calculating a pairwise distance matrix through Gaussian Radial Basis Functions (RBF) to ensure the prediction is rotation-invariant.

Step 4: Drug Repurposing Similarity Search & The RAM Optimization

To discover how chemically similar the molecule is to existing drugs and identify bodily targets: 1. Morgan Fingerprints: The molecule is translated into a 2048-bit mathematical fingerprint. 2. Tanimoto Similarity Score: Compares fingerprints using intersection over union. 3. Memory-Mapped Chunking: [v2 Update] The 5.5 GB uncompressed matrix is memory-mapped (mmap_mode='r') and processed in chunks of 10,000 to keep RAM strictly under 80 MB, preventing system crashes. 4. Target Mapping: Matches (Tanimoto > 0.10) are cross-referenced with a dataset of 5,421 PDB targets, displayed in the dedicated Drug Discovery tab.

Step 5: 3D Protein-Ligand Interaction Profiling & PyMOL AI Assistant

Once a target is identified, the dedicated 3D View tab offers a split-pane interactive workspace: 1. Interactive Protein Mapping: Fetches raw PDB files from RCSB, caching them locally, and uses BioPython to identify bound ligands. 2. Interaction Profiling: Calculates non-covalent physical forces (Hydrogen Bonds, Hydrophobic Contacts, Pi-Stacking, Salt Bridges) dynamically. 3. PyMOL AI Assistant: Type natural language commands (e.g. "show spheres") into the right-hand chat panel. The local Ollama LLM translates it into raw PyMOL/3Dmol.js commands. 4. GNINA Molecular Docking: [v2 Update] A massive addition allowing one-click integration with GNINA. The background worker physically docks your drawn molecule into the fetched protein pocket and streams back the estimated binding affinity (CNN Pose Score) in real time.

Step 6: ADME Drug-Likeness Profiling (Lipinski & Veber Checks)

Pharmaceutical filters are evaluated in the dedicated ADMET tab to score drug-likeness. 1. Lipinski’s Rule of Five: Checks Molecular Weight (< 500 Da), LogP (< 5), Hydrogen Bond Donors (<= 5), and Acceptors (<= 10). 2. Veber’s Filter: Checks Rotatable Bonds (<= 10) and Polar Surface Area (<= 140 Å²). 3. Deep ADMET Neural Network: [v2 Update] An advanced AI panel predicting deep toxicological profiles (mutagenicity, hERG blocking, blood-brain barrier permeability) to provide modern pharmacological context beyond standard Lipinski rules.

Step 7: Maximum Common Substructure (MCS Align)

[v2 Update] A new scaffold alignment tool that takes multiple SMILES strings, isolates their overlapping core structure, and dynamically overlays them in the 3D viewer to highlight conserved chemical properties.

Step 8: Unified HPC Compute Architecture

[v2 Update] The architecture has shifted from blocking the Python web server to a robust Microservice Topology. - Redis Broker: Acts as the message queue between the UI and the heavy lifters. - Celery Worker: Dedicated background process executing MD Simulations, GNINA Docking, and AI inferences. - Compute Dashboard: A dedicated tab containing a live Activity Log terminal tracking the internal status of the background workers without freezing the interface.
